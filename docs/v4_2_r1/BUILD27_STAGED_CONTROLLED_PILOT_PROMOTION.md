Exact production-signed Build 27 (`1.0.0-rc.17+27`) is approved for a staged
controlled pilot. The authorization is bound to APK SHA-256
`00846ABFD6342C938C7228601B528664C2FBC3B265B9BF74EF53607D3092AD6C`,

## Staging rule

The first stage is limited to two approved users on two named physical devices.
Each device must receive the exact APK directly from governed custody, upgrade
in place when already installed, and produce a privacy-safe handout receipt.
Both canary targets must pass launch, authentication, clean synchronization and
one representative user-owned operation through a normal operating shift
before the roster expands.

Mutating business-flow convergence has not yet been claimed for exact Build 27.
The canary is the controlled place to gather that evidence. A failure stops
further handout; it is not waived because server recovery exists.

## Excluded channels and changes

GitHub Actions artifacts are construction custody only and must not be used as
the distribution channel. GitHub Releases, Firebase App Distribution, Play
Console, Play Store, web links, public links and unrestricted distribution are
not approved. This decision does not change IAM, activate App Check, clear
device data or authorize a Firebase business-data mutation.

## Actual handout

This promotion record authorizes the bounded pilot but does not claim that a
new handout occurred. Every actual handout must freeze its approved user/device
entry and record the exact package hash, signer continuity, installation result,
startup result, synchronization result and stop-condition status without
storing raw account or device identifiers in repository evidence.
