## Contradictory creation recovery

Recovery distinguishes recovered, pre-existing identity, deferred and
contradictory evidence. After recovery is attempted, contradictory or uncertain
evidence cannot fall through to generic batch mutation. An ordinary existing
record update is admitted only before replay after a fresh server identity
check; that identity is not proof of an old acceptance or frozen command.

The regression's batch double can succeed, and the forbidden cases assert zero
calls. Local edits survive and unrelated work can continue. Native Isar tests
also persist a contradiction hold, reopen the store and show that the next pass
still cannot dispatch. If reading the hold collection throws, the affected
records are deferred before network activity with an in-memory diagnostic.
Absent-store/web behavior and a fully durable command journal are not certified
by these tests.
